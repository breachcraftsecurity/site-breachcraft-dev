name-research

Availability is a small part of naming. This answers should we.

One pipeline, every stage a provider behind the same contract: generate, check availability, measure search dominance, volume and collisions, then return a verdict. Stages are swappable, repeatable and diffable.

Usage

python run.py audit entrapath cloudbreachlabs
python run.py websearch "breach craft" --json
python run.py recon example.com
python run.py judge --file shortlist.txt

Sources answer separately and are marked for corroboration; one source alone is recorded as single_source.

Reading a verdict

  • blocked — an existing same-industry entity. Drop it.
  • contested — one exact hit, usually fiction or coincidence. Read the hits.
  • clean — no exact results.
  • unknown — a provider failed. Not a pass.

Assessment work, not just naming

The same repo carries the engagement stages: plan the scope, add and hash evidence, retest for drift, report a finding against a contract, and review the bicep that ships the fix. Companies House, sanctions, certificate transparency, urlscan, VirusTotal and DNS posturing are commands, not copy-paste scripts. A worked example with real hashes sits in the repo.

Limits, stated so a pass is not over-read

Scores sort within a run; they are not probabilities and should never be quoted as one. An API that is down returns unknown, which is a gap, not a result. Search dominance is a snapshot of the search engine's index on the day, and volumes are vendor estimates. Whether a name is any good still needs a person.

Tests

273 tests, offline, no keys. Provider shapes are faked with recorded responses so the contracts stay tested without a network.
