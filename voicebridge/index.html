voicebridge

The briefing goes out as audio. The evidence stays in your database.

For engagements where the interaction is a phone call: dial, record both channels, take the answer back, transcribe it and log every event locally instead of trusting a provider console to keep it.

Usage

python run.py serve --port 8099
python run.py call +447700900001 --record
python run.py send +447700900001 --wav brief.wav --text "briefing"
python run.py log

The webhook needs HTTPS. A quick tunnel is enough locally; a named tunnel gives a stable hostname, and the signatures are computed against it, so the public base must match.

What it does

  • TwiML served with correct escaping, dual-channel recording optional.
  • Signature validation on every route; a tunnel URL alone does not let someone inject audio.
  • Outbound audio as MMS, or WhatsApp where a UK long code cannot do MMS, plus plain text either way.
  • Webhook downloads recording media immediately, before the provider's retention expires it.
  • Transcription by Twilio or Whisper; Whisper keeps client audio on the host.
  • Every event in SQLite with direction, peer, SID, status, paths and transcript.

Limits, stated so a pass is not over-read

UK long codes cannot send MMS; WAV outbound needs a US or Canadian number, a short code, or WhatsApp. Twilio fetches media server-side, so the file must be publicly reachable, not a local path. Recordings at the provider expire on a schedule, which is why the download is immediate. This moves audio; it does not do speech analytics.

Tests

9 offline tests: TwiML escaping, signature accept and reject, public URL derivation, recording parameters, sender validation and a log round-trip.
